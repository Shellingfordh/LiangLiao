# M4 设计：可感知的平行人生

状态：**已确认设计，待实施**。本设计是《送给你这个回来的人》的 M4 阶段规格；它不改变已确认的聊天优先、原创资产、Lua 事实驱动和 Maker 运行时边界。

## 1. 目标

M4 让用户在打开对话前后都能感知到：若夕在另一座城市按自己的时间继续生活。体验不依赖开放世界，也不依赖运行时 LLM；它通过有限人生档案、可阅读的人物档案、与事件同源的场景状态包，以及场景中的生活痕迹完成闭环。

核心循环为：**观察当前状态 → 对话基于生活事实 → 离开 → 生活继续 → 回来发现变化**。

## 2. 非目标

- 不做开放地图、自由移动、自由镜头或热点找物。
- 不接入运行时 LLM、真实天气、新闻或在线 Tripo/Marble 调用。
- 不把 Marble 高面数网格作为移动端运行时场景。
- 不把骨骼动作作为 M4 交付前置条件。
- 不做无限档案、自动清理或完整存档管理器。

## 3. 人生入口与存档

冷启动默认恢复最近打开的一段人生并直接进入聊天。用户主动打开设置层后，可使用三个明确入口：

| 入口 | 行为 |
| --- | --- |
| 查看档案 | 只读打开角色档案，不切换人生 |
| 换一段人生 | 显示已有的人生卡片并切换 |
| 新故事 | 选择城市与关系起点后创建独立人生 |

一张人生卡就是一份完整、互不串写的存档，包含城市、关系起点、聊天记录、事件计划、共同记忆、最近打开时间与当前生活痕迹。最多保存三段；创建第四段前必须由用户明确选择要替换的卡片。随机只保留为新故事中的次要选项，不作为默认入口。

## 4. 角色档案页

档案页只读展示以下由当前人生单源派生的信息：城市、当地时间、身份、关系起点、近期生活线索、当前状态，以及一条当前生活痕迹。它不得复用为换档案选择层，也不得暴露调试术语或原始事件键。

## 5. 场景状态包

每次由时间表和 EventService 确定的事件事实，必须生成同一份 `SceneState` 供状态窗、档案页和回复事实使用：

```text
sceneId / backgroundKey
colorTemperature / keyLightDirection
characterPlacement / groundShadow
microMotion
recentTrace { assetKey, anchorX, anchorY, layer }
future3D { sceneRef, anchorId }
```

首批资产为四城各四张原创 4:3 基础静帧，共 16 张：居所、工作场所、公共停留处、街区或通勤过渡处。每张静帧必须预先定义人物站位、色温、主光方向和接地阴影；场景缺图时必须显式回退，绝不沿用旧图并假称已切场景。

## 6. 2.5D 生活痕迹

基础背景是静帧；便签、半杯咖啡、唱片、雨伞等是不可点击的 2D 覆盖物，以归一化锚点、层级和缩放定位在背景上。它们只用于观察，不构成收集或数值玩法。

每段人生只展示一条当前生活痕迹，绑定最近确定的关键事件，并在下一重要事件后替换。档案页用短文本说明同一事实。将来升级为 3D 时，复用 `anchorId` 将同一痕迹放进对应场景坐标；不改变事件或存档语义。

## 7. 人物与动作风险门

M4 先交付静态前景人物与无骨骼微动，例如轻微呼吸、重心、朝向或镜头变化。每个场景必须单独设置光色、主光、站位和接地阴影，人物不得再像独立贴图。

**骨骼动作是明确风险门。** 任何 idle、看手机、坐下或走路动作接入前，必须依次验证：源 GLB 带可用骨骼与动画、导入后的 MDL 保留骨骼节点与动画轨道、Maker 真机能正确播放。任一步失败即回退为无骨骼微动，M4 场景和档案验收不受阻塞。

## 8. 资产来源与未来生成

所有图像、覆盖物、角色和文字必须为原创。若本会话暴露 Maker 资产生成 MCP，优先用该工具产出并保留结果映射；若没有可用工具，则为网页端人工生成提供逐张提示词、4:3 尺寸、人物留白和导入清单。生成资产需按项目规则登记来源、提示词、尺寸、运行时路径和资源引用。

## 9. 验收

1. 最近人生冷启动直达聊天；三段人生可切换且聊天、事件、痕迹互不串写。
2. 档案页正确展示当前城市、当地时间、身份、关系起点、近期线索和当前状态。
3. 16 个场景状态均具备正确背景、光色、主光、人物站位、接地阴影及可选痕迹锚点。
4. 重进或切换人生后不出现旧城市、旧场景或旧生活痕迹。
5. 骨骼动作未通过验证时仍以静态人物和无骨骼微动稳定运行。
