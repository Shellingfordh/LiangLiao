# 《送给你这个回来的人》游戏设计理论与同类产品研究

日期：2026-09-26｜用途：为 [PRD](PRD.md) 的体验机制、内容设计和验收提供依据。

> 方法：读取理论原文、竞品官方功能页与项目本地规格。竞品条目是**公开资料分析，未登录付费功能，也未实机体验**；“可借鉴”属于本项目设计推论，不表示竞品已验证本项目方案。没有沿用竞品的角色、美术、文案或故事。

## 1. 研究问题与结论

问题：在 Maker 只能用 Lua 事实、模板回复与固定镜头状态窗的前提下，如何让“她有自己的生活，而用户回来能看懂发生了什么”既可玩又不制造被冷落感？

结论：设计一个**观察线索 → 自主发问 → 事实回应 → 离开 → 看见后果**的闭环。系统给角色独立日程，给用户解释线索和提问权；一条重要事件最多留下一个当前物件痕迹，并在对话、档案中以不同形式重复同一事实。忙碌时展示消息状态和可探索的已有线索，不靠焦虑、签到或强制通知维持回访。

## 2. 理论如何变成设计约束

| 理论与原始来源 | 理论真正支持什么 | 本项目推论与可验收需求 |
| --- | --- | --- |
| [MDA：机制、动态、体验](https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/) | 设计者需要在规则、运行中行为和玩家感受之间往返验证；不是“加功能就有情绪”的公式 | 目标体验是安静的好奇与可信的牵挂；机制用城市时间、事件、回复和痕迹；测试问用户能否从可见线索推断一次生活变化，而非统计背景张数 |
| [游戏中的自我决定理论研究](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf) | 自主性、胜任感、关系感与游戏乐趣相关；研究不证明任何具体陪伴产品能实现这些效果 | 自主性＝用户选发问/离开/切人生，不强迫签到；胜任感＝线索可被理解并在回复中得到验证；关系感＝过去共同经历有连续回指。不能把“角色独立”做成无解释的长期沉默 |
| [Jenkins：游戏设计作为叙事建筑](https://web.mit.edu/~21fms/People/henry3/games%26narrative.html) | 空间和物件可以承载可发现的过往事件；重要信息应在多个可遇见的媒介中被辨认 | 一件痕迹必须能指回具体事件，放在与事件相符的场景；画面是线索，档案给简要事实，对话按用户所问补完。三者可互证而不逐字重复 |

理论是**构思工具**，不是本项目的效果证明。后续效果必须通过用户任务观察与真机演示检验。

## 4. 设计差异与机制细化

### 4.1 差异不是“也有记忆和 3D”

陪伴产品已公开提供对话记忆、形象、语音、主动消息；真实时间游戏也已公开提供离线变化。本项目要验证的组合是：**一个原创角色、一个有因果的当地生活时段、一次由用户发起的谈话、一个事后可指认的空间痕迹**。竞争位置来自这些要素的同源性，而非单项功能的首创。

### 4.2 两个节奏

- **短节奏（一次打开，约半分钟即可获得价值）：**看到地点与可用性 → 找到一条线索 → 自由发问或离开。角色睡着时仍可看到已有线索，输入被保存；不为了“首会话成功”临时叫醒角色。
- **长节奏（跨几个当地时段）：**事件发生 → 回复时引用 → 痕迹出现 → 重进后档案概括 → 下一关键事件替换当前痕迹。错过现场不会失去关键叙事；回返只总结与当前状态有关的少量事实。

### 4.3 线索、提问、验证

每个准备进入内容池的关键事件应交付四件东西：①玩家先能看见/读到的线索；②至少一种自然可问的方向；③事件事实允许的回复边界；④事后留下的一个场景痕迹及生命周期。例：若夕在洛杉矶书店活动前整理资料（事件）→ 状态窗桌上有手写便签（线索）→ 用户问“明天在忙什么？”（自由输入）→ 模板根据事件事实回答（验证）→ 活动结束后保留一张折起的活动单（痕迹）。此例是**新内容设计示范，不表示资产或代码已经存在**。

若用户问了模板无法理解的问题，回复应承认未能接住问题并只表达已知事实，不能把事件模板伪装成对任何问题都精确作答。应在测试中专门输入与当前线索无关的问题，记录“答非所问”和“事实矛盾”。

### 4.4 自主性与等待的边界

角色可以忙，但用户无需替她完成任务、刷好感、按时回来。等待态说明依据可见状态，不显示伪精确倒计时或假已读；同一夜里多次打开不奖励更多事件。若未来加入主动消息，默认关闭，由用户选择频率和静默时间，内容须指向真实存档事件，不能使用内疚、威胁失去关系或假危机促回访。

### 4.5 内容经济

现有 16 景是“在哪里”的基底，不等于 16 段独立剧情。先丰富每城的**事件四件套**，要求相邻回访能区分“日程常态”和“一次具体事件”。当前一次只显示一条痕迹，旧痕迹的事实仍可留在档案/记忆中；不要无限叠加覆盖物。新增内容按“城市身份是否独特、关系起点是否改变表达、痕迹能否回指事件、是否与既有事实冲突”筛选，而非按模板句数筛选。

## 5. 优先级与实验

| 优先级 | 产品假设 | 验证方式 | 失败信号 |
| --- | --- | --- | --- |
| S1 发布前 | 现有一条痕迹已足以让用户认出回返变化 | 非团队用户完成一次可重现的离开/重进任务；指出事件、痕迹、回复的关系 | 只能看到“换图了”，说不出发生了什么 |
| S1 发布前 | 忙碌/睡眠解释使等待可信 | 给首次用户一个角色暂不可回的状态，观察其理解和下一步 | 以为消息丢失、已读不回，或认为必须守着屏幕 |
| P1 | “事件四件套”比单纯增加背景更能提升生活感 | 同等试玩时间比较现有内容与一组新事件内容的回返复述 | 增加文案后仍只记住背景，或回复答非所问 |
| P1 | 用户选择提问方向能提升自主感 | 先用可编辑的线索提示做原型，不锁死自由输入；访谈其是否感觉在决定对话 | 感到被选项推着走、只是在点剧情按钮 |
| P2 | 可进入场景比固定状态窗带来额外价值 | 单场景真机原型，比较“能发现的新事实”与操作成本 | 只是能走动，未增加可解释的信息，且干扰聊天 |

样本建议 5–8 位非团队用户做形成性观察，只用于发现问题；不得把小样本结果写成普遍留存率。所有比较都需在相同城市/事件事实下进行，避免把新增剧情的效果误算给画面或操作。

## 6. 证据边界

资料核对时间为 2026-09-26。MDA（2004）、自我决定理论游戏研究（2006）和 Jenkins 的叙事建筑论文属于经典原始研究，可用于提出假设，不能替代当前用户验证。竞品功能来自各自官方页面，属于较高可信度的**功能描述**，但营销效果、付费层实际表现和用户长期体验均未实测，不能据此推断本项目的效果。本项目 2026-09-25 的实施与真机状态仍以 `CHANGELOG.md` 和 `BLOCKED.md` 为准。本文未触发 Maker 构建，也没有把 P1/P2 写成 S1 已交付。
