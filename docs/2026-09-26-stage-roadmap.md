# M5–M10 阶段实施路线

日期：2026-09-26｜主文档：[PRD §6](PRD.md)｜状态依据：[CHANGELOG](../CHANGELOG.md)、[BLOCKED B-6](../BLOCKED.md)

本路线把“能做成什么”与“平台宣传能生成什么”分开。阶段完成以用户可见结果和对应设备证据为准；下文为计划，除注明本地已验证者外均不表示已交付。全程使用原创角色、场景、文本和资产。

## 2. 阶段卡

### M5：可控的新故事（当前进行中）

- **输入：**M4 三段人生、四城×四关系、已有用户预览发现的显式选择串写。
- **已做：**显式两轴确认、单一随机入口、新槽存档清理与落盘；本地 UrhoXRuntime 自检 34/34 场景、280/0 判定，Lua LSP 零 Error。此处只记录 [M5 变更日志](../CHANGELOG.md)的证据。
- **剩余：**Maker 最新代码云端构建，Android 实点“先关系后城市”“只点城市”“上海×前同事”“成都×高中同学”、满槽替换和随机；强杀再进。逐次记构建标识、设备、时间与卡片/标签/档案/场景/存档结果。
- **出门条件：**每条路径的用户选项与最终人生一致，未选齐不创建，另两槽不变；失败先回 M5 修复，不把本地自检记成真机通过。

### M6：Tripothon S1 可玩封版（M5 真机通过后）

- **输入：**M5 真机通过；M4 既有一条可演示事件链、16 景、角色、痕迹。
- **产品：**陌生用户能在短会话看懂若夕此刻状态，发消息后理解等待；跨时段或明确标注的演示回返能指出一件事如何进入回复、档案和场景痕迹。
- **制作：**Maker 固定可玩构建与测试码；复验 Android 冷启动、换段、新建、痕迹、夜景/光影、消息顺序和错误路径。用 Maker 网页端设有效 icon，整理至少三张真实设备截图、一段 90–120 秒含操作的录屏、原创资产看板及 Tripo/Marble 来源说明。不得把 Marble 录制镜头说成实时手机画面。
- **证据：**[PRD A1–A9](PRD.md)逐项记录“通过/失败/未测”、构建标识与设备；至少一条现有事件链按线索→发问→事实回复→痕迹→回返走通；5–8 位非团队试玩者用于找理解断点，未完成观察就标“未测”，不以小样本宣称留存效果。
- **出门条件：**可玩 Demo、实机录屏和视觉资产看板齐，发布面 icon/截图实际生效，Android 强杀恢复成功；按[赛事官方交付要求](https://developers.tripo3d.ai/en/events/tripothon-s1)提交前复核当期页面。

### M7：事件四件套覆盖（赛后，M6 体验记录后）

- **内容范围：**先每城一条关键事件，不把 16 个地点等同 16 段剧情。每张卡写清前置线索、自然发问方向、Lua 固定事实与回复禁区、事后痕迹及生命周期；普通日程事件不强求物件。
- **Maker 交付：**事件实例键稳定；离线补算与重复打开不重复产出；同一人生的状态窗、档案和回复引用同一事件。自由文本无法匹配时只回答已知事实，不能假装精准理解。
- **Tripo/Marble：**先复用 M4 场景；确实缺表达时，Marble 只补原创 4:3 静帧并显式入 `resources.json`，Tripo 才补立体痕迹并走 GLB→MDL 导入。先看内容是否能解释，再决定做资产。
- **出门条件：**四城各一张事件卡和至少一次回返路径；相邻两次回访可辨，且 5–8 位非团队用户能从画面/档案/回复说出对应事件。说不出时修线索或措辞，不能只增加背景张数。

### M8：一件可选择的礼物（M7 通过后）

- **最小故事：**用户在聊天里主动选择送出一件与已发生经历相关的原创小物；若夕按当前事实接受或拒绝；接受后在固定状态窗中出现，档案留下来源；拒绝时说明原因，不悄悄摆上。
- **资产：**Tripo 提供低模道具源文件，记录授权/来源、面数与导入产物；Maker 负责 MDL、材质、贴图、prefab、资源打包和真机性能；Marble 可给静帧里的桌面/房间摆放参考，不能把重网格直接当主场景。
- **规则：**只有一次明确选择，无价格、稀有度、收集表或关系分数；每段人生独立保存选择与摆放位置；切换、重进和替换时按槽读写。不要在用户未送出时伪造“她收到你的礼物”。
- **出门条件：**送出/拒绝/冷启动/换段/满槽替换均可复现；真机可见、不遮挡聊天与现有线索；用户能解释此物为何留在她的生活里。

### M9：固定镜头下的自主活动（M7 后可与 M8 分开验证）

- **T1 最小 Spike：**在一个现有场景沿预设航点移动现有角色，镜头固定，无用户移动控制。逐帧更新通过 `main.lua` 唯一 `Update` 订阅转发到模块 `Tick`。本地已证明真实模型会沿路径移动，仍缺云端和手机画面验收。
- **T1 出门条件：**角色不会出窗、穿过痕迹或改变事件事实；能从移动看出“她在做什么”，而不只是增加动感。记录真机帧率、内存、包体、合成与静态版本差异；收益不清楚就保留静态窗。
- **T2 独立门：**只有 Tripo 网页/其他经授权的原始动画实际导出，并在 Maker 导入后证明 skin 与动画轨道保留，才把 idle/walk 动作接上。Maker MCP 的 rig 不等于动作；两个阻断都过后再测步频、停走过渡和 Android 表现。
- **回退：**T2 不通时可用 T1；T1 观感或性能不通时继续使用 M4 静态窗。Marble 镜头录像可供宣传和背景参考，不能替代游戏内交互验收。

### M10：可进入空间的决策 Spike（条件研究）

- **前提：**M9 已有固定窗活动与真机性能基线，并能说清“进入房间”将揭示哪条固定窗表达不出的生活事实。
- **实验：**仅选一间房；Marble 提供空间母版，Maker 以可负担的低模资产搭场，Tripo 供人物/小物；记录导入、帧率、内存、包体、载入时间、镜头/操作与聊天路径是否互相干扰。Marble Collider 或高质量 GLB 仅是减面 Spike 候选。
- **决策：**与同一事件的固定窗版本比较，若用户确实发现额外事实且手机性能和交互均过关，再另开产品实施阶段。失败则停在固定窗；本路线的 M10 只交付 go/no-go 证据，不承诺开放地图。

## 3. 不排进主线的条件分支

- **外部 LLM 润色：**[M2-B 设计](2026-09-23-m2b-llm-gateway-design.md)已有代码与契约，但部署、Maker 客户端出站/服务端白名单和真机端到端未闭环。只有外部依赖逐项过门后才可做一项独立实验；Lua 事实仍为唯一真源，失败回落模板，日志不留私聊全文。
- **跨设备同步：**`clientCloud` 目前只留接口。本地三段人生存档是已验链路；若以后做同步，须单独验证异步回调、冲突、断网和隐私语义，不以预览存档成功代替云同步已交付。
- **语音、音效与视频：**Maker MCP 的语音、音乐、音效、视频是构建期内容工具，不是运行时叙事引擎。只有用户研究指出表达缺口，才为特定事件挑原创音画素材并做真机体积/体验验证；视频生成遵循 Maker 工具要求的显式请求与审阅门。

## 4. 共同验收纪律

1. 每阶段留一张“版本/设备/时间/操作/期望/实际/截图或日志”的证据表；本地、自检、编辑器预览、Android 真机分栏。
2. 新背景显式加入 `.project/resources.json` 的 `groups.default` 与 `preload_groups`；Tripo 源 GLB 要转换为 Maker 运行时 MDL/材质/贴图/prefab，保留[资产真源](asset-provenance.md)。
3. 云端构建/预览/提交依 Maker 项目工具链；构建前保留需要的 `runtime.log` 证据，避免 `--reset` 清掉尚未转录的真机记录。
4. 每个阶段只以自己的出门条件宣告完成；M4 预览完成不抵扣 M5、M6 的 Android 门，后续画面和用户研究也不能倒写成 S1 已有功能。
