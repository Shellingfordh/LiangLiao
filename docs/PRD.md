# 《送给你这个回来的人》产品需求文档

版本：v2.2｜2026-09-26｜范围：Tripothon S1 可玩 Demo 与 M5–M10 阶段路线

> 本文是产品范围和验收主文档。实施状态以 `CHANGELOG.md` 为准，发布前缺口以 `BLOCKED.md` B-6 为准。本文的未来目标不表示已经上线。

## 1. 定位与用户价值

**一句话：**用户在聊天中认识原创角色林若夕。她生活在另一座城市，与用户共享真实时间，按自己的日程继续生活；用户回来时能从对话、场景和留下的物件看见这段时间发生了什么。

这是一份“送给回来的人”的小世界：它记得共同经历，并在下次相见时给出可观察的变化。最小价值是**同一生活事实在时间、回复、档案和状态窗中一致出现**。聊天是主界面；固定镜头状态窗是观察入口。第一阶段用 2.5D 背景、一个 3D 原创角色与少量生活痕迹呈现“小世界，高生活密度”。[定位来源](https://github.com/Shellingfordh/LiangLiao/blob/main/read.md)

### 1.1 用户与场景

- 面向愿意和原创虚构人物持续交流，又不希望被签到、好感度或任务清单驱动的人。
- 一次使用可以很短：看当地时间和当前状态，留一条消息，稍后回来。
- 用户可能在异地或睡前打开；角色的忙碌、睡眠和延迟必须可理解，等待不能像惩罚。

### 1.2 产品承诺

| 承诺 | 用户能看到的证据 |
| --- | --- |
| 她有自己的时间 | 城市当地时间决定地点、可用性、事件和回复时机 |
| 她的生活继续 | 离线时段按确定规则补算，重进后出现有界的经过摘要 |
| 对话来自生活 | 回复只引用已确定的时间、地点、事件和关系事实 |
| 经历留下痕迹 | 关键事件对应档案线索与场景物件，回来后仍可辨认 |
| 用户保有选择权 | 用户决定发什么、何时回来及是否切换人生；满槽替换须明确选择 |

**非目标：**开放地图、自由镜头、任务战斗、好感度数值、无限人设、实时生成世界、真实天气/新闻、永远即时回复。所有角色、场景、文本、音乐和视觉资产必须原创，不复刻已有 IP。

### 1.3 设计定位与判断依据

[同类产品与游戏研究](2026-09-26-game-design-competitor-research.md)表明，对话记忆、形象、主动消息和真实时间变化都已有成熟先例。本作要验证的组合是：**一个角色有独立日程，用户自主选择谈话，回返时可从物件、档案和回复中重建一件事**。不以对话长度、角色数量或场景面积作为价值代理。

按 [MDA](https://aaai.org/papers/ws04-04-001-mda-a-formal-approach-to-game-design-and-game-research/)倒推，目标体验是安静的好奇、可信的牵挂和“我看懂了她这一天”的满足；对应机制是当地时间、事件、异步消息与可解释痕迹。按[游戏中的自我决定理论研究](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf)，用户需要保留选择何时说、说什么、何时离开的自主性，并能凭线索理解结果。理论用于设计假设，效果由试玩验证。

## 2. 核心循环与关键路径

```text
观察她在哪里、能否回复
 → 用户交流
 → Lua 确定事件事实与关系记忆
 → 同一事实进入回复、档案和场景痕迹
 → 用户离开，世界按时间推进
 → 再回来，看见并理解变化
```

### 2.1 首次进入

新用户选城市与关系起点，生成独立人生后直达聊天。城市为上海、成都、洛杉矶、伦敦；关系为陌生网友、高中同学、前同事、久未联系的朋友。人格核心不随配置变化；城市决定身份、日程和生活事件，关系决定开场与称呼语气。随机选择是次级选项，结果创建时落盘。

### 2.2 发消息与等待

首页可看到当地时间、当前地点和简短可用性。发送后消息留在时间线；忙碌或睡眠时不伪造“已读”。到可回复状态时先固化交付事实，再按 FIFO 逐句显示回复。输入、等待、后台与重进不能造成消息丢失、重复或乱序。用户离开等待界面是正常行为。

### 2.3 回来时

打开最近人生。经过多个时段时，仅呈现能解释当前状态的少量事件线索，不倾倒完整日志。状态窗、档案与回复应让用户回答“她刚才经历了什么，为什么现在在这里”。

### 2.4 “Gift”的具体含义

本届 Demo 的礼物是**被记住且能再次进入的共同时间**：一次对话留下可见痕迹，再回来仍可认出。PR 中“送物件进入房间”是远期能力，当前没有完整的资产、摆放与存档验收。未来若做可赠物件，须先验证用户可选择、角色可接受或拒绝、摆放可恢复，且不转为付费数值系统。[定位来源](https://github.com/Shellingfordh/LiangLiao/blob/main/read.md)

### 2.5 可玩性：线索、发问、验证

用户每次打开都应有一条可理解的路：**看见线索 → 决定是否发问 → 收到基于事实的回应 → 下次回来辨认后果**。短会话即使遇到若夕睡眠，也能看当地时间、当前场景和已有线索，留下消息后退出；系统不得为了首会话转化临时叫醒她。跨时段会话以最近一件关键事件为锚，重进后只总结与当前状态相关的经过，不要求用户补看完整时间线。

这不是侦探解谜。痕迹要给人推断空间，档案与回复再补足事实；不以谜题正确率卡住聊天。用户问无关问题或没有发问时，世界照常推进，但模板不能假装理解了所有自由文本。[环境叙事依据](https://web.mit.edu/~21fms/People/henry3/games%26narrative.html)

## 3. 页面与交互需求

| 页面/入口 | 必须完成 | 禁止或回退 |
| --- | --- | --- |
| 聊天首页 | 当前人生、当地时间、状态窗、消息流、输入框、设置入口 | 3D 操作喧宾夺主；暴露调试键 |
| 状态窗 | 当前场景、原创角色、状态说明、可选生活痕迹 | 旧图配新地点，伪称换景成功；点击收集 |
| 设置层 | 查看档案、换一段人生、新故事 | 满额自动重置 |
| 档案页 | 城市、当地钟点、身份、关系起点、≤3 条近期线索、当前状态与痕迹 | 原始事件键和可编辑事实 |
| 人生卡 | 最多三段，展示城市、关系、最近打开时刻与线索 | 第四段静默淘汰旧段 |

- 输入、已发送、等待、逐句回复和错误提示应可区分；“正在输入”只在实际开始交付时出现。
- 忙碌或睡眠用自然语言解释，不能虚构精确已读时间或承诺何时必回。
- 首次遇到忙碌状态时，消息可送达且草稿/记录可恢复；页面给出可看的已有线索与明确离开路径，不用倒计时诱导守候。
- 背景装载失败时保留聊天并给明确说明，不能沿用旧图假称已切换。
- 软键盘旁按钮的实际实例必须设 `focusable=false`；条件子控件不能通过含 `nil` 的 `props.children` 列表挂载。这两点已有静默失效实测。[Maker 取证](maker-lua-api-verification.md)

## 4. 时间、事件、消息与存档

### 4.1 单一事实链

`可信 UTC → 城市偏移与当地时段 → 日程/可用性 → 事件实例 → SceneState → 回复、档案、状态窗 → 人生存档`。

Lua 是时间、事实、去重和存档的唯一裁定方。事件实例应具备稳定的 `eventId / occurrenceKey / cityId / sceneId / startUtc / endUtc / state / traceKey`；回复记录其依据的交付事实。场景缺失、事件过期或资料不全时使用同城明确回退，绝不能引用别城或旧人生。

### 4.2 时间与离线推进

- 用 `common.get_server_time()` 取得权威 UTC；四城按明确生效区间处理夏令时；`os.date` 使用 UTC 模式。
- “离开后继续”是**重进时按时间窗和稳定种子补算**的离线模拟，不宣称后台进程一直运行，也不伪称真实天气或新闻。
- 事件以人生、城市、日期/时段和模板构成稳定键；重复打开同一段时间不重复交付事件或痕迹。
- 用户修改设备时钟不能改变权威事实；跨日与 DST 边界可复现。

### 4.3 回复与内容

- 用户自由输入。当前发布范围以原创 Lua 模板和变量表达既定事实，不能宣称未发生的事、错误地点或错误可用性。
- Maker 单机客户端**没有运行时 LLM 接口**。M2-B 网关的设计和代码不等于已部署、已接通；客户端出站、服务端 URL 白名单和真机端到端均未闭环，故不列入 S1 功能承诺。[平台实测](maker-lua-api-verification.md) · [M2-B 状态](2026-09-23-m2b-llm-gateway-design.md)
- 将来启用润色时，只能改措辞；超时、断网、解析或事实校验失败立即使用已存事实模板。诊断日志不得保存私聊全文。

### 4.4 关系与存档

每段人生独立存城市/关系、聊天、待回复、事件、记忆和当前痕迹，最多三段。切换或新建后，旧人生城市、场景、对话、痕迹不进入当前页面。满三段时先由用户选待替换卡片。旧单档迁移保留备份；注册表损坏时优先从人生文件恢复。

### 4.5 内容生产规则（新增事件时适用）

每个拟进入内容池的**关键事件**须先写一张“事件四件套”卡：①用户在回复前可见的一条状态或场景线索；②至少一个自然可问的方向，但保留自由输入；③Lua 确定的事实与回复允许/禁止的表述；④事后的一条痕迹及其场景、持续到何时、被什么事件替换。线索、对话、痕迹指向同一 `occurrenceKey`；三处表达互补，不机械重复同一句话。新增普通日程事件可不留痕，不为填满画面强行制造“重要事件”。

内容审查以四个问题为门：这件事符合该城身份与作息吗？关系起点是否只改变说话方式而不改硬事实？用户能否从痕迹回指事件？连续两次回访会不会只看到同一模板换名词？若任一答案不清楚，先改事件卡，再增加背景或句池。已交付 16 景与当前痕迹继续按 M4 规格运行；完整“事件四件套”覆盖率属于 M7 内容扩展，不倒写成 M4 已完成项。[环境叙事依据](https://web.mit.edu/~21fms/People/henry3/games%26narrative.html)

## 5. M4 可感知的平行人生：世界、画面与平台边界

### 5.1 M4 场景

四城各四类地点，共 16 个原创 4:3 场景状态包：居所、工作场所、公共停留处、街区/通勤过渡处。每包声明背景、色温、主光方向、人物站位、接地阴影、无骨骼微动和痕迹锚点。背景静帧上叠加 Tripo 来源的原创低模角色及不可点击的 2D 痕迹。状态窗用固定镜头，不提供自由移动。

状态窗、档案和回复共用同一 `SceneState`。痕迹只在绑定场景显示，且每段人生一次只展示一条当前痕迹。夜间光色表达当地时段，但不宣称已有独立夜景图。

### 5.2 三平台职责

| 平台 | 本项目用途 | 运行时与验证边界 |
| --- | --- | --- |
| TapTap Maker | 唯一运行时：Lua、UI、状态窗、存档、云端构建、真机发布 | 模型加载 MDL；资源须进入打包清单；画面与性能取真机结论 |
| Tripo | 构建期原创角色和道具 3D 来源 | GLB 经导入转 MDL/材质/纹理/预制体；rig 和动画逐关验证 |
| Marble | 构建期城市空间、4:3 静帧、全景和镜头参考 | 游戏运行时不调用；高质量网格默认不进移动端主场景 |

Tripo 官方 API 有多视图生成、减面、rig 和动画 retarget，但不能据此推断 Maker MCP 当前有动画操作，也不能推断导入后 skin/轨道可播。[Tripo 官方接口](https://developers.tripo3d.ai/en/docs/introduction) Marble 官方高质量网格约 60 万至 100 万三角面、Collider 网格约 10 万至 20 万三角面；移动端导入前须独立测单场景包体、帧率、内存与加载时间。[Marble 官方规格](https://docs.worldlabs.ai/marble/export/specs)

所有资产在 [资产真源表](asset-provenance.md) 中记录来源、原始文件、处理步骤、运行时文件与权利。新背景显式列入 `.project/resources.json` 的 `groups.default` 和 `preload_groups`。骨骼动作须依次通过源 GLB 骨骼/轨道、导入 MDL/动画轨道、Maker 真机播放三关；失败则继续无骨骼微动。

### 5.3 M4 产品验收与证据边界

M4 的产品判据为：三段人生独立且恢复最近打开段；档案、对话和状态窗引用同一城市、关系、事件与痕迹；16 场景无错误背景，人物站位/光影与场景一致；重进与换段不残留旧城市、旧景和旧痕迹。2026-09-25 用户已依据 Maker 编辑器预览判 M4 完成，详见 [M4 规格](superpowers/specs/2026-09-24-m4-perceivable-parallel-life-design.md)与[变更日志](../CHANGELOG.md)。Android 强杀恢复和部分真机观感另列发布前回归，不能反向称为 M4 阶段未完成，也不能因阶段完成而省略发布回归。

## 6. 阶段路线与平台分工

阶段号表示**可独立验收的产品结果**，不是功能数量。M5、M6 是 S1 交付主线；M7 起是赛后扩展，各阶段按下述依赖和平台门槛决定是否投入。M0–M3 的既有能力与 M4 的完成判定见 [变更日志](../CHANGELOG.md)：M4 已由用户在 Maker 编辑器预览判完成，Android 强杀和画面回归仍属于发布门槛。

| **M8 可选择的礼物与留痕** | 用户主动送出一件小物，若夕有符合事实的回应，重进仍看得见；**M7 通过后候选** | 单件道具、送出/接受或拒绝的固定规则、每段人生独立存档；固定镜头内摆放，不开放自由拖拽或收集经济 | Tripo 生成原创低模道具并经 GLB→MDL/材质/贴图/prefab 转换；Marble 只供摆放参考或静帧 | 送/拒/重进/换段/满槽替换无错放与丢失；真机可见且包体与帧率经记录；非团队用户理解物件与共同经历的关系 |
| **M9 固定状态窗的自主活动** | 角色在现有小窗中沿预设路径移动，画面仍服务聊天；**可在 M7 后独立试验** | 先做 T1 固定镜头无骨骼移动的单场景真机 Spike，过关后再扩到适用场景；由 `main.lua` 的唯一 Update 驱动 | 复用现有 Tripo 角色和 Marble 静帧；T2 idle/walk 需先拿到动画数据并解决 skin 导入丢失，属于独立验收门 | 同一事件/城市下，动作不遮挡线索、不穿出画框、不因重进改变事实；真机帧率、包体、画质与静态回退逐项记录。T2 未过则停留 T1 或 M4 静态状态窗 |
| **M10 可进入空间的可行性判断** | 判断进入一间房是否增加可发现的生活信息；**条件研究，不承诺上线** | 一间房的镜头与交互原型，先量真机帧率、内存、包体和操作对聊天的干扰 | Marble 只供空间母版/录制镜头；若采用其网格必须减面并单独性能 Spike。Tripo 供低模角色/道具，动画仍受 M9 的 T2 门槛约束 | 原型比固定窗多传达可复述的事实，且真机性能与操作均可接受，才另立正式交付阶段；否则保留固定窗 |

依赖关系：**M5 真机通过 → M6 封版 → M7 内容验证 → M8 礼物**。M9 可在 M7 后与 M8 分开验证；M10 只有 M9 的空间/动作证据和单场景性能数据具备时才启动。M7–M10 均不写入本届 S1 的功能承诺。阶段所需的人手、资产与平台外部条件详见 [阶段实施路线](2026-09-26-stage-roadmap.md)。

M6 不能以本地 Windows 截图替代真机观感，M5 本地自检也不等于 Android 触控与强杀通过。[发布前清单](../BLOCKED.md)列出尚缺的设备与发布面操作。M6 内容封版先选**一条**已实现的事件链逐格走查；M7 才扩大“四件套”覆盖。M2-B 外部润色网关、`clientCloud` 跨设备同步、Tripo 网页动画和 Marble 高面数场景均需各自的部署/格式/真机门，不能因平台宣传能力而自动加入任何阶段。

### 6.1 S1 演示脚本（90–120 秒）

1. 0–20 秒：展示当地时间、场景和她暂时忙碌的原因。
2. 20–45 秒：用户发送与眼前线索有关的消息，显示等待而非假已读。若剪入时间推进，明确标注，不能伪称现实即时发生。
3. 45–75 秒：状态/地点变化，回复与事件一致，场景出现一条痕迹。
4. 75–100 秒：重新进入，档案线索与痕迹对应；切到另一段人生，城市、对话、痕迹独立。
5. 100–120 秒：展示 Tripo 原创角色来源、Marble 空间/镜头参考与 Maker 真机运行画面。

录屏应是 walkthrough，不做只有氛围没有操作的预告。赛事官方要求可玩 Demo、屏幕录制和视觉资产看板；公开 build log 可选。[Tripothon S1](https://developers.tripo3d.ai/en/events/tripothon-s1)

## 8. 用户研究与质量指标

S1 样本小，先做 5–8 位非团队试玩者的任务观察：首次进入 30 秒内能否说出她在哪、为何晚回；遇到等待时会做什么；回返后能否指认**哪件事**造成了画面变化；问一个无关问题时是否觉得回复“装懂”；换段后能否认出独立人生。逐人记录“看到的线索→提出的问题→理解的事件→仍困惑之处”与操作路径，不把私聊全文写入分析日志。目标是找理解断点，不伪造留存率的统计显著性。

区分三种失败：**事实矛盾**（必须修单一事实链）、**事实正确但看不懂**（优先修线索和表达）、**期待自由聊天但模板无法覆盖**（明确产品能力边界并评估后续内容/技术）。不得用“玩得更久”单独判定成功，因为延长等待也会增加时长，却可能损害体验。

质量以真机启动、致命错误、关键操作成功、存档恢复、场景误配和可感知光影衡量。帧率与包体在真机测量前只能作为预算，不写为已达成的性能承诺。

## 9. 风险与回退

| 风险 | 回退或验证 |
| --- | --- |
| 生成资产精美却无法移动端运行 | 守住已验角色与静帧；高面数场景只作录屏/看板，3D 单开 Spike |
| “继续生活”表现得像随机切换 | 稳定时间窗/种子、实例去重、多表同源；矛盾时退回基础模板与场景 |
| 等待造成焦虑 | 解释可用性，不给假已读或精确承诺；演示时间推进明确标注 |
| 回访被做成签到或错过惩罚 | 同夜反复打开无额外奖励；错过现场仍能通过摘要理解关键事实；不设连续天数、内疚式推送或假危机 |
| 城市与关系选择串写 | 封版前修复并真机回归，不用宣传文案掩盖 |
| 编辑器与真机表现不同 | 用 Android 实际画面和 `runtime.log` 收尾，本地运行时只判逻辑与装载 |
| 网关或联网不可用 | S1 依赖本地 Lua 模板；外部网关保持关闭直到独立部署/白名单/真机验收 |
| 素材权利不清 | 不进入发布包或宣传物，资产真源表登记原创链与授权 |
