## 1. 一句话故事

你打开手机，发现收件箱里多了一封来信：「你来过的小镇，现在很好。回来看一眼吧。」——你推开镇口的大门，三位角色还记得你上次说的话，会主动告诉你这几天镇上发生了什么，而你也可以留下来陪他们到天黑。

> **礼物主题（A Gift for ______）：送给你这个「每次回来都会被记得」的人。**

---

## 2. 为什么是这个题

### 2.1 创意（30%）—— 用「平行时间线 + 自动事件」打破 NPC 假死

传统陪伴型游戏的问题：**NPC 不会自己活着**。你离开，他们就是贴图；你回来，对话树重启。

我们的做法：

- 角色基于游戏内时间和现实时间差，自主生成「事件」（做了什么、想了什么、写了什么）
- 你回来时，他们已经「活过了一段」
- 记忆持久化（云存档 + 本地存档双层）
- 角色头顶气泡显示「他们现在正在想/做」
- 你可以翻看他们的「日记」——时间戳是真实的，文字是 LLM 按人设生成的

### 2.2 主题契合（20%）—— 直接命中「A Gift for ______」

- 礼物对象：**每一个孤独时打开 App 的人**
- 礼物本身：**一个会自己运转的小镇**
- 触发情绪：被记住、被陪伴、不需要解释的关心

### 2.3 完成度（25%）—— 7 天可交付

- 1 个 Maker 项目（≤7 天能跑通核心循环）
- 3 个角色模型（Tripo P1 文本生成，预计 30 分钟出）
- 1 套事件触发器（Lua 协程，不依赖外部服务）
- 录屏 + 截图 + README + 演示链接（标准三件套）

### 2.4 传播潜力（15%）—— 自带分享属性

- 「我回来时他给我留了封信"是天然社媒爆点
- 小红书话题 #Tripothon 可冲 Mac Mini

### 2.5 商业价值（10%）

- 陪伴类应用有付费订阅潜力
- 角色 IP 化（每个角色可独立衍生内容）

## 3. 角色设定（二次元风格）

| 角色 | CV 气质 | 摊位 | 性格关键词 | 触发事件类型 |
| --- | --- | --- | --- | --- |
| **小满** | 暖系少女 | 面包店 | 早起、记口味、嘴硬心软 | 「你喜欢的口味今天出炉了」「下雨天闭店」 |
| **阿泽** | 清澈少年 | 图书馆 | 安静、博学、偶尔毒舌 | 「读到一本想到你的书」「阴天不开窗」 |
| **奶奶** | 慈祥老奶奶 | 镇郊菜园 | 慢节奏、爱操心、记得日期 | 「你上次说喜欢番茄，今天正好熟了」「节气提醒」 |

> 三个角色的「事件生成器」由**不同 prompt + 不同触发条件**驱动，自然产生差异化。

## 4. 技术架构

### 4.1 系统拓扑

```
┌─────────────────────────────────────────────────┐
│             TapTap Maker（客户端 + 服务器）       │
│ ┌─────────────┐  ┌──────────────┐  ┌──────────┐ │
│ │ 场景/资源层 │  │ Lua 脚本层   │  │ Maker AI │ │
│ │  • 3D GLB   │  │  EventSched  │  │  对话/事件│ │
│ │  • Spine    │  │  TimeSync    │  │  生成     │ │
│ │  • UI 主题  │  │  MemoryIO    │  │          │ │
│ └─────────────┘  └──────────────┘  └──────────┘ │
│        ↑                ↑                ↑      │
│        └──── clientCloud ────┴── serverCloud ──┘│
│                  (角色记忆 / 时间戳 / 日记)         │
└─────────────────────────────────────────────────┘
                    ↑
            (用户从 TapTap 启动)
```

**关键约束**：
- TapTap Maker 是 **UrhoX + Lua + WASM** 闭源引擎，无法注入 Python/JS 服务端代码
- 「LLM 调用」由 **Maker 内置 AI** 承担——它的能力由我们设计的 prompt / Skill 决定
- 「持续时间」由 **Lua 协程 + 时间戳存档**实现

### 4.2 三大子系统

#### 子系统 A：角色模型（Tripo 出）

- 用 `text_to_model` P1-20260311 出 3 个二次元 GLB
- prompt 模板：「A cute anime-style 二次元 girl, [角色描述], full body, T-pose friendly, single character, soft lighting, white background, no accessories on hands」
- 参数：`face_limit=8000`, `texture=true`, `pbr=true`, `auto_size=true`
- 直接 GLB 落到 Maker `assets/models/`（无需转换）

#### 子系统 B：事件生成器（Maker AI + Lua 调度）

```text
事件触发条件（Lua 端）:
1. 距离玩家上次访问 >= 1 小时 → 「想你」事件
2. 现实日期是角色生日 → 「生日」事件
3. 游戏内时间到早上 7 点 → 「面包出炉」事件（小满专属）
4. 游戏内时间到下雨 → 「闭店不开窗」事件（全员）
5. 玩家进入角色 5 米内 → 「打招呼」事件
6. 每 10 分钟 → 「日记」事件（自动写一段内心独白）

事件内容生成（Maker AI）:
输入：角色人设 + 最近 3 条事件 + 当前时间 + 玩家上次消息
输出：JSON { type, title, body, emotion, duration_sec }
```

#### 子系统 C：平行时间线（Lua + clientCloud）

```lua
-- 伪代码
local last_visit = clientCloud.get("last_visit_ts") or now()
local elapsed_hours = (now() - last_visit) / 3600

if elapsed_hours >= 1 then
    show_event("想念", generate_message())
end

-- 写日记（每天一次）
if not diary_written_today() then
    write_diary(role_id, generate_diary(role_id))
end

-- 离线事件累积（基于时间差反推）
local offline_events = estimate_offline_events(elapsed_hours)
for _, ev in ipairs(offline_events) do
    push_event_log(role_id, ev)
end
```

```
T+0    玩家首次进入：镇口信箱亮起一封信
        「这是你继承的小镇。他们在等你。」

T+30s  走进面包店，点小满
        小满：又是你啊（玩家名字）。今天的盐可颂刚出炉，
        记得你上次说过喜欢——拿一个？

T+2min 走进图书馆，点阿泽
        阿泽：……你前天借的那本《雪国》看完了吗？
        我翻到一段想给你看。

T+5min 走到镇郊，点奶奶
        奶奶：哎呀来啦？刚摘的小白菜，带点回去。
        （看日历）再过三天立冬了，记得添衣。

T+10min 关闭 App
        （背景）小满继续卖面包、阿泽继续整理书架、奶奶继续种菜——
        在时间戳层面发生。

T+24h  玩家再次打开
        信箱新信件：「你想知道我们这一天做了什么吗？」
        → 「小满的日记：今天下雨，闭店。烤了 8 个可颂，
          想着如果你来就好了。」
        → 「阿泽的日记：收到出版社寄来的新书。封面像你上次
          提到的那片海。」
        → 「奶奶的日记：小白菜长大了。等你来看。」

T+25min 玩家再次走到角色身边
        头顶气泡：「想跟你说件事……」
```

## 7. 风险与回退

| 风险 | 影响 | 回退方案 |
| --- | --- | --- |
| Tripo 出的二次元人物不像二次元 | 风格割裂 | 多次 prompt 迭代 / 改用 H3 高保真 / 加 `negative_prompt: realistic, photographic` |
| Maker AI 不能稳定按 system prompt 扮演 | 对话跑题 | 在 Skill 里固化 prompt / 用结构化输入 |
| 时间差事件触发不准 | 体验断裂 | 简化方案：只做「想念」「生日」「下雨」三类 |
| Maker 引擎限制无法精确调度 | 离线事件缺失 | 只在玩家进入瞬间计算离线累积，简化版也能成立 |
| 角色不会动 | 静态感强 | 用 Maker 内置 Spine 做情绪气泡动画 |

## 10. 关键设计决策记录

| 决策 | 选项 | 选定 | 原因 |
| --- | --- | --- | --- |
| 方向赛道 | 游戏 / XR / 应用 / 影视 / 实体 | **📱 应用** | Maker 是闭源引擎，做应用类最稳；游戏次之 |
| 主题文学性 | 送给某个具体的人 vs 抽象的「陪伴感」 | **「回来的人」** | 抽象但有具体触发（你离开 → 他们继续活） |
| 角色数 | 1 / 3 / 10 | **3** | 太多分薄注意力，1 缺少小镇感，3 是黄金数 |
| 时间线是否真实 | 真实 wall clock vs 游戏内加速 | **真实 wall clock** | 「离线后他们继续活」需要真实时间戳 |
| 离线事件来源 | 真「模拟运行」 vs 进入时反推 | **反推** | Maker 引擎限制，无法后台跑；进入时按时间差生成可信 |
| AI 角色扮演 | Maker AI 全自动 vs 预制 Skill | **预制 Skill + Maker AI** | 稳定性 + 可控性兼顾 |
| 美术风格 | 像素 / 写实 / 二次元 | **二次元** | Tripo 能直接出，主题契合（用户原话） |

## 11. 实现验证要求（必过项）

后续实现与提交前，必须按以下顺序逐项验证，未通过项不得进入下一项：

1. **游戏是否能正常开始**
   - TapTap Maker 预览 / 实机测试入口可正常进入主场景。
   - 角色模型正确加载，场景无黑屏 / 白屏 / 崩溃。
2. **操作是否符合预期**
   - PC：WASD / 方向键移动、鼠标点击对话 / 交互、鼠标拖拽旋转视角。
   - 手机：左侧虚拟摇杆移动、右侧点击角色触发对话、双指缩放 / 旋转视角。
   - 所有交互在 2 次点击内可完成，无菜单卡死。
3. **成功、失败和重新开始是否完整**
   - 成功：玩家可触发至少一个情感反馈事件（想你 / 生日 / 下雨 / 日记）。
   - 失败：定义明确的失败条件与提示（如网络超时、存档损坏、模型加载失败），并有“重试 / 重新开始”入口。
   - 重新开始：支持从头开始 / 回到上一次存档点，且状态恢复一致。
4. **画面在目标设备上是否清楚**
   - 目标设备：Maker 实机测试手机 + PC 预览。
   - 角色与 UI 在真机分辨率下可读、无严重锯齿 / 掉帧。
   - 3D 模型面数控制在移动端可接受范围（建议 `face_limit <= 5000`）。
5. **是否存在卡住流程的问题**
   - 从进入到触发首个事件，无死循环、无无限 loading、无对话卡死。
   - 离线时间检测准确，不会出现事件不触发或重复触发导致流程中断。
   - 所有必交物（Demo / 录屏 / 截图）可在流程内正常生成。

> 验收顺序固定为 1→5，前一项未通过时禁止推进到后一项。
