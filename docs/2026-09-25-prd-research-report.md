# PRD 深度调研与决策报告

日期：2026-09-25｜对应文档：[PRD](PRD.md)（2026-09-26 已更新至 v2.1）

> 后续的游戏设计理论、同类产品对照和机制优化见 [2026-09-26 专题研究](2026-09-26-game-design-competitor-research.md)。本报告保留 2026-09-25 的平台与定位决策快照。

## 研究问题

如何把 PR #1 的“会继续生活、可观察、可留下变化的平行世界”定位，落成在 TapTap Maker、Tripo、Marble 现有边界内可交付、可验收的 Tripothon S1 产品？

## 结论

采用**聊天优先的“可观察世界”**作为 S1 交付：真实时间推导生活状态，Lua 固化事件事实，回复、档案与 16 个场景包共享该事实，关键事件在 2.5D 画面留下一条痕迹。先完成 Android 发布前回归和赛事交付物，再研究用户送物件或进入完整 3D 空间。此顺序保留定位材料的“再回来”价值，同时不把未验证的运行时能力写成承诺。

## 主要取舍

1. **以可解释的回返差异衡量“世界活着”**。背景数量是素材量，不能替代同一事件在回复、档案和痕迹中的一致性。
2. **保留聊天作为主操作**。定位材料的“进入世界”是愿景；当前 Maker 状态窗先提供观看，不扩成自由移动、自由镜头或物品收集。
3. **将“Gift”落实为共同时间留下痕迹**。可赠物件具有方向价值，但需要接受/拒绝、摆放、持久化与权利规则，作为赛后独立验证。
4. **按平台最窄可证能力写需求**。Tripo API 支持动画处理，不代表本项目 Maker MCP 或导入后的 MDL 已可播放。Marble 可输出高保真世界，不代表移动端能承载其网格。M2-B 网关代码存在，不代表运行时 LLM 已接通。
5. **用真实设备封版**。现有本地逻辑自检和 Maker 编辑器预览支持阶段结论；Android 强杀恢复、光影、阴影、场景过渡与发布素材仍要单独取证。

## 冲突与不确定性

- 定位原文把“最终可以真正走入 3D 场景”作为远景；当前项目硬边界是固定镜头、无自由移动。两者处于不同阶段，不把愿景写成 S1 承诺。
- Tripo 官方 API 的动画能力比项目当前 Maker 工具可用操作广；是否能在真机交付取决于导入后的 skin/轨道和播放验证。
- Marble 官方提供网格导出，但规格量级与本项目移动端预算不匹配；适用性只可由单场景真机 Spike 判定。
- M4 编辑器预览完成与 Android 强杀恢复属于不同证据；截至本报告依据的 B-6 快照，后者未闭环。
- 比赛规则与平台权益可能变化；提交前再看官方页面。未独立核实用户账户对应的 Marble/Tripo 订阅权益、Maker 发布审核结果。

## 下一步执行顺序

1. 先修创建时城市/关系错配，按选项落盘和重进分别验收。
2. 用包含最新修复的 Maker 构建在 Android 完成 B-6：冷启动、换段、痕迹、阴影与夜景，并保留构建号和截图/日志。
3. 在 Maker 发布面板确认 icon，补真实设备截图，录 90–120 秒 walkthrough，准备原创资产看板。
4. 封版后以 5–8 名非团队试玩者观察“能否解释她为何晚回、回来后发生了什么”；再决定是否做可赠物件或可进入 3D。

## 方法与信心

2026-09-25 核对指定 GitHub PR/文件、平台官方文档、赛事官网和仓库最近的验收记录。产品定位与当前工程状态信心高；未来赠物和完整 3D 的体验效果尚无用户或真机证据，信心低，故列为探索而非承诺。未以竞品营销文案或登录墙快照推断 Maker API。
